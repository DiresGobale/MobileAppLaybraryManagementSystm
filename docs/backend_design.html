03

Loan Issue Workflow — Transactional Sequence

POST /api/loans/issue · atomic · 8 steps · rolls back on any failure
📱Flutter
App
🛡Express
Middleware
🛣loanRoutes
/issue
📖loanService
.issue()
🗄SQLite
(transaction)
📤Response
1
Flutter → POST /api/loans/issue with body { userId, bookId, overrideLoanDays? } and header Authorization: Bearer eyJ...
2
requireAuth verifies JWT → extracts req.user = { id, role, username }. 401 if expired/invalid.
3
requireLibrarianOrAdmin checks req.user.role ∈ (librarian, admin) → 403 if student tries to issue.
4
validate runs express-validator on body → 400 if userId/bookId missing or non-integer.
5
loanService.issue() opens db.transaction(() => { ... })() → TX BEGIN. Any throw below = full rollback.
6
TX step 1: Reconcile overdue → UPDATE loans SET status='overdue' WHERE status='active' AND due_date < now.
7
TX step 2: SELECT * FROM users WHERE id=? AND is_active=1 → 404 USER_NOT_FOUND if missing.
8
TX step 3: SELECT * FROM books WHERE id=? → 404 BOOK_NOT_FOUND if missing; 409 NO_COPIES if available_quantity = 0.
9
TX step 4: SELECT COUNT(*) FROM loans WHERE user_id=? AND status IN ('active','overdue') → 409 LIMIT_EXCEEDED if ≥ max (default 3).
10
TX step 5 — CAS decrement: UPDATE books SET available_quantity = available_quantity - 1 WHERE id=? AND available_quantity > 0 → if changes() = 0 throw 409 RACE (concurrent issue grabbed last copy).
11
TX step 6: INSERT INTO loans (user_id, book_id, issued_by, issue_date, due_date, status) VALUES (..., 'active') → captures lastInsertRowid.
12
TX step 7: INSERT INTO notifications (user_id, title='Book Issued', message='...', ...) → student sees confirmation in their inbox.
13
TX step 8: INSERT INTO activity_logs (user_id=librarianId, action='loan_issue', details='Issued book #X "..." to user #Y. Due ...') → audit trail entry.
14
TX COMMIT → all 8 steps atomic. If anything between step 5 and here threw, ROLLBACK undoes the decrement, the loan row, the notification, AND the activity log — no partial state.
15
loanRoutes → returns 201 Created with the loan row JSON.
16
On any failure: the next(err) chain calls errorHandler → maps AppError to its status code, or SQLite constraint to 409, and returns JSON { error, code }. The Flutter app shows the user a friendly message.
